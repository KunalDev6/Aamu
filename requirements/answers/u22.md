# U22 — pairing-code lifetime and private configuration, 14 November 2026

## Pairing-code lifetime

The user selected: **Until used.**

Pairing codes have no time-based expiration and are consumed when redeemed. A consumed code cannot be redeemed again. This supersedes the unresolved expiry question and the older 24-hour proposal.

Engineering representation: explicitly set `PAIR_CODE_TTL_SECONDS=0` for until-used codes. An unset value still means code creation is not configured; positive values remain supported as explicit second-based expiry for tests/alternative configuration, not the selected product lifetime.
